# devrc — NixOS / home-manager dotfiles

Personal dev-environment config (zsh, tmux, neovim, i3, scripts) for the workbench + laptop NixOS hosts. Managed by **home-manager via a flake**.

## Shell environment (read before running commands)
- **Bash tool runs NON-interactive zsh** (`zsh -c`) → sources `.zshenv` only, NOT `.zshrc`/`initContent`. Shell tweaks Claude needs at runtime must go in home-manager `programs.zsh.envExtra` (→ `.zshenv`). `unsetopt nomatch` lives there so unmatched globs pass through literally instead of aborting with "no matches found".
- zsh reserves `status` — use `rc=`/`out=`, never `status=$(...)`.
- Use `git -C <path>` and absolute paths — never `cd <repo> && …` (triggers approval prompts and can run untrusted hooks).
- **Canonical env handles are pre-exported in `.zshenv`** (via `envExtra`) so you don't re-`cd`/`export` on every call — non-interactive `zsh -c` doesn't persist state. Use them directly (each is existence-guarded, absent on hosts without that checkout): repo roots `$DEVRC` `$HOMELAB` `$DATAPACKET` `$CIVITAI` (e.g. `git -C $DATAPACKET status`); kubeconfigs `$KC_HOMELAB` `$KC_WORKBENCH` `$KC_DPPROD` `$KC_NEBULA` (e.g. `KUBECONFIG=$KC_DPPROD kubectl get pods`). There is deliberately **no default `KUBECONFIG`** — pick a cluster per command so a bare `kubectl` can't hit prod.

## Applying changes
- **Deploy to BOTH hosts (after merge):** `scripts/ship.sh` — converges workbench + laptop to `origin/main` (fetch → `merge --ff-only` → `home-manager switch` → verify HEAD==origin/main) in one idempotent call. **It never stashes** (the stash is repo-GLOBAL and would reach into other worktrees — see RULES.md "Git Workflow"); a host it cannot fast-forward, or one with a conflicted/mid-merge tree, is **skipped and left exactly as found**, with the blocking files named. Use this instead of hand-running the per-host dance; `--no-laptop`/`--no-local` to scope. Covers home-manager only (not `sudo nixos-rebuild`).
- **Apply config (single host):** `home-manager switch --flake ~/workspace/devrc --impure` (allowlisted). This is how you validate a Nix edit end-to-end.
- **Quick syntax check** before switching: `nix-instantiate --parse <file>.nix >/dev/null`.
- **NEVER `sudo nixos-rebuild` from Claude** — can't sudo non-interactively. System-level changes must be staged as an apply script for the user to run (see the `laptop` skill's `stage-system` pattern). home-manager (user-level) is fine.

## Server / headless mode
- `~/.server-mode` marker toggles graphical bits: `headless-mode` (disables dunst/espanso) vs `graphical-mode` (re-enables), both run a home-manager switch. A host may be in server mode — check for the marker before assuming a GUI.

- `scripts/collector/` + `scripts/validation/` — the **personal activity-telemetry pipeline**: 6 sources (zsh/tmux hooks, X11 keylogger, Brave ext [nav+scroll], Claude-session tailer, i3 window/workspace focus) → `emit` → `collector.py` (systemd user daemon) → dedicated authed homelab ClickHouse `activity.events` → Grafana dashboard; `validation/` is the deterministic harness; `scripts/session-analysis/activity-scan.py` is the on-demand "where time goes + what to automate" report; `scripts/session-analysis/initiative-scan.py` is the **cross-repo initiative + progress ledger** (handoff docs + git + telemetry → momentum/next-step), operated via the **`/initiatives`** slash command. **Claude-session telemetry now has three layers in `activity.events` (source=claude):** the **message stream** (`kind=prompt|command`, `claude/tailer.py`), **Layer A deterministic session rollups** (`kind=session-summary`, `claude/session-tailer.py` — tool/token/lang/git counts; the telemetry-native successor to the built-in `/insights` `~/.claude/usage-data` cache, NO LLM; **emit-on-settle** — one row on first sight, one per `CLAUDE_SUMMARY_INTERIM_HOURS` (4) while live, and one each time the transcript idles `CLAUDE_SUMMARY_SETTLE_MINUTES` (20), incl. after a `--resume`; append-only, so **dedupe on read via `argMax(…, ingested_at)` per session**), and **Layer B qualitative facets** (`kind=session-insight`, `scripts/session-analysis/session_insight/` — underlying goal/outcome/Claude-helpfulness/friction + automation-opportunity/recurring-toil/workflow-gap; **division of labour is fixed: deterministic Python does the plumbing (`prepare`→scrub+chunk+attach Layer A as ground truth; `write`→validate+`emit`), the LIVE Claude session running the `activity` skill does the extraction step — NO `claude -p`, no external API**; append-only → argMax dedupe; on-demand only, no timer; an anti-confabulation contract forbids the model from inventing/restating counts). `scripts/session-analysis/insights.py [--days 14] [--insight-days 30] [--json] [--host H] [--html PATH]` renders the report from Layer A + the message stream + Layer B (OUTCOMES + leverage-ranked automation/toil/gaps sections) and degrades gracefully when telemetry is off. See `scripts/session-analysis/README.md`. **Operate it via the `activity` skill** (endpoints, creds, gotchas, deploy). Gotchas that bite: `ts` is UTC (dashboard buckets local); laptop must use its nebula CH endpoint; both hosts are hostname `nixos` so `ACTIVITY_HOST` disambiguates; `home-manager switch` DOES restart the daemons on a script change now (X-Restart-Triggers). Browser `active_ms` was retired (broken on i3) → attention is i3-derived.
- `scripts/initiatives/` — the **initiatives subsystem**: a durable, queryable counterpart to the on-demand `initiative-scan.py` scan (`store→sync→viewer→recaps→router→assistant`). A workbench 15-min `systemd --user` timer (`sync.py`, serverMode-gated) writes the scan's output into an `initiatives` schema in the **homelab `mailbox` Postgres** (same DB as `mail_actions`, via `mail-actions/_db.py`); a serverMode-gated viewer (`viewer.py`) serves it at **http://192.168.50.250:8899** (workbench eth1 — NOT `.94`) with LLM recaps (homelab `vllm-recap` Qwen2.5-7B), a signal→initiative `route.py`, and a read-only `/api/ask` assistant. **Operate via the `initiatives` skill.**
- `scripts/mail-actions/` — **email-automation layer** over the self-hosted mail inbox (the Postgres `mail` table; separate from activity telemetry). Deterministic Stage-1 filter → LLM action-required extraction → `mail_actions` queue (one live action per thread, auto-closes when you reply) + invoice→`taxes-{year}-invoices` MinIO archiver (daily systemd timer `mail-actions-archive`) + a sibling Gmail Sent-mail IMAP poller running as a homelab CronJob. Action-extractor is manual (`extract.py run`, the only LLM/$ piece); archiver is scheduled. **Operate via the `mailbox` skill.**
- `scripts/repo-cos/` — **repo "chief-of-staff"** ("agents bring me ideas" / CEO model): weekly `serverMode`-gated workbench timer (`repo-cos.timer`, Mon 08:00) deterministically scans the repos for improvement signals (TODO/FIXME, skipped tests, `latest` tags, churn) → cheap LLM synthesis (OpenRouter, survivors only) → top-5 evidence-backed proposal digest. **SELF-HOSTED mail** (defaults): **sends** via Zach's postfix relay `From: repo-cos@mail.zacx.dev` (DKIM-signed; via a `kubectl port-forward` to the production cluster), **Reply-To `repo-cos@inbox.zacx.dev`**; his reply routes to the homelab Postgres `mail` table and `feedback.py` **reads it from Postgres** (via `mail-actions/_db.py`). Gmail-SMTP/IMAP kept as fallbacks (`REPO_COS_SEND`/`REPO_COS_REPLY_SRC`). `exclusions.py` then deterministically acts on the reply TWO ways: **repo-level** ("paused"/"not owner" → HARD-DROP the repo; `resume <repo>`) **recommendation-level** ("skip"/"not needed" → dismiss just that proposal by its evidence `file:line`, keep the repo), and **approve** ("approve"/"yes"/"lgtm" → POST a durable **clawgate Task** via `clawgate.py`→`/api/tasks` for one-tap Dispatch, suppress-on-success) — state in `~/.config/repo-cos/exclusions.json` (`"repos"`+`"dismissed"`+`"approved"`), + context-injects the rest. Needs BOTH kubeconfigs (prod relay + homelab pg) + `kubectl`/`psycopg2` (best-effort). Creds: `~/.config/repo-cos/env` (OpenRouter). **Operate via the `repo-cos` skill.** ⚠ gotcha: `feedback.py` loads `mail-actions/_db.py` by explicit importlib path — do NOT add `mail-actions/` to `sys.path` (its `llm.py` shadows repo-cos's → breaks synthesis).
- `scripts/browser-bridge/` — the **agent-driveable live-Brave automation layer**: Claude drives Zach's REAL logged-in Brave (live cookies/session, not headless) via a loopback token-authed rendezvous server (`server.py` on `127.0.0.1:8788`) ← outbound long-poll ← an MV3 extension (`extension/`, loaded unpacked per Brave profile), operated through the `browser` CLI (`html`/`text`/`eval` (alias `js`)/`tabs`/`nav`/`screenshot`/`click`/`type`/`key`/`upload`/`wake`/`activate`/`frames`/`whoami` + an autonomous **opencode browser-agent** that offloads open-ended browsing to a cheap RCE-hardened model). Multi-instance (per-profile routing keys) + per-session tab isolation, a per-instance rate-limit backstop, and metadata-only telemetry into `activity.events`. Home-manager-deployed: a `browser-bridge` `systemd --user` service (`nix/home.nix`) runs the server, and the `browser` skill is symlinked to `~/.claude/skills/browser/`. **Operate via the `browser` skill.** Gotchas that bite: **run `browser whoami` FIRST** to know which host (both are hostname `nixos`) + profile you're driving; **an extension code change needs a FULL Brave restart, not just ↻** (the long-poll keeps the old service worker alive, so reload often no-ops) — **`browser --instance <label> ping` is the deterministic tell** (new build → `{pong,extensionVersion,id,ops}`; a build older than the op → `unknown_op`; bare `ping` with two profiles connected → 409 ambiguous), and `whoami`/`health` carry a per-instance `extension_stale` verdict (`null` = undecidable, never "fine") plus `extension_id` = `chrome.runtime.id`, which is **path-derived** and so is the only field that says WHICH DIRECTORY Brave loaded (✅ MEASURED 2026-08-01 on both hosts: `sha256(abs path)[:32]`, each nibble `0-f`→`a-p`, **path only, no profile component** — so the id is predictable in advance; repo path → `pkkoninbaeicfalpdkkmcknhnacjjjpi`, deployed path → `bgbkamdlkdleahpgdgmjipjbgmepgenk`; read the "before" id off the `brave://extensions` card BEFORE clicking Remove, which wipes `chrome.storage.local`); the extension itself is home-manager-copied to **`~/.local/share/browser-bridge-ext/`** (Brave must be pointed there — loading it out of the repo lets another session's `git checkout` swap the code out mid-verification; ⚠ this is immune to git, NOT to a concurrent session's `home-manager switch`, which rewrites the deployed tree from ITS working tree; and per the flake rule a NEW extension file must be `git add`ed or it is silently omitted from the deploy; re-pointing + rollback are manual per-profile `brave://extensions` steps, see `extension/README.md`), and any extension change that must be provably loaded MUST bump `manifest.json` AND add a new discriminator; and **never reach for `activate` to fix a hidden/unrendered tab** — it STEALS the operator's screen (telemetry caught 1–5 calls/minute). Use **`browser wake`** (CDP focus emulation, un-throttles a hidden/background tab with **NO focus movement**) or `--wake` on `text`/`html`/`eval` (un-throttle + read in one session) — and wake **once per page, not per read**: the rendered DOM persists after the debugger detaches. `activate` is the **LAST resort** for things that genuinely need the real foreground (it moves the screen via `i3-msg`), and is unreachable by the autonomous agent. Prefer the **`js` alias for `eval`** in worktree-isolated agents — the isolation guard refuses any command containing the token `eval` (the wire op stays `eval`). `screenshot` writes a mode-**0600** `.png` to disk (auto-pruned after 24h; no base64 to stdout) and `html` has a `--max-bytes` cap (default 32768). **SKILL.md was restructured (#233/#235)** into a lean ~11.9KB core (12,288-byte ceiling) + 8 on-demand reference files at `scripts/browser-bridge/reference/{agent,css-hit-test,errors,frames-cdp,security-ops,spa-wake,tabs-instances,x-fallback}.md`, ~10,700 tokens saved per browser task; the core addresses them by **repo-absolute path** because `nix/home.nix` symlinks only `SKILL.md` + the `browser` CLI into `~/.claude/skills/browser/`, NOT `reference/`. ✅ **`browser agent` now WORKS** — verified end-to-end 2026-07-31 (`{"answer":"Example Domain",…,"status":"ok"}`). It had TWO independent blockers, both now fixed: an `$(...)` stdout flush race truncating the fail-closed gate's input (#216), and a readiness probe that ran `eval '1'` on `about:blank`, which `chrome.scripting` cannot inject into (#234). ⚠ **Every doc misattributed this to an opencode version problem for the entire arc** — don't re-diagnose it that way.
- `scripts/dl-router/` — the **media download router**: files browser downloads straight into the right subject directory of a local media library using PAGE CONTEXT (tags/og/JSON-LD), not the filename. A loopback token-authed sidecar (`server.py` on `127.0.0.1:8791` — 8790 is taken) owns the directory index, alias store (SQLite under `~/.local/share/dl-router/`), dedupe and a deterministic matcher (no LLM); a **separate** MV3 extension (`extension/`, separate from browser-bridge on purpose — a routing bug must not take down the agent command channel) answers Chrome's `onDeterminingFilename` with `"<dir>/<name>"`. Above threshold → auto-file + undo toast; below → keyboard picker; every correction writes an alias. Home-manager-deployed (`dl-router` `systemd --user` service, `yt-dlp` package, `dl-route` CLI on PATH, skill symlink). **Operate via the `dl-router` skill.** ⚠ Three things that bite: the library root is a **live qBittorrent seeding target** so `backfill apply` moves torrent-backed files via `torrents/setLocation`, never `mv` (and SKIPs everything when qBittorrent state is unknown); `onDeterminingFilename` **cannot escape the download root**, which is why the Brave profile's `download.default_directory` must BE the library root (`setup-brave-profile.sh`, Brave closed); and an extension code change needs a **FULL Brave restart**. 🔴 The library is PRIVATE and this repo is PUBLIC — never commit a real path, directory name, filename or the route log; all config lives in `~/.config/dl-router/`.
- `claude/` — **global Claude Code config managed declaratively** (`RULES.md`, `PRINCIPLES.md`, **all slash-commands under `claude/commands/`**, and **all skills under `claude/skills/`**). `nix/home.nix` symlinks these to `~/.claude/` via `home.file` (commands + skills recursively → each lands as `~/.claude/commands/<name>.md` / `~/.claude/skills/<name>/…`), so both hosts stay in sync (they were drifting when edited per-host). **Edit `claude/*.md` / `claude/commands/*.md` / `claude/skills/**` here + `home-manager switch`/`ship.sh` — NOT `~/.claude/*` (read-only nix-store symlinks).** ⚠ A skill fix is NOT deployed by merging it — the live copy stays on the previous generation's store path until a switch. Flake gotcha: a NEW command/skill file must be `git add`ed before it switches (flakes only see tracked files). New-host caveat: `home.file.force` does NOT clobber a pre-existing *foreign* `~/.claude/RULES.md` or `~/.claude/commands/*.md`; `rm` the foreign ones once before the first switch. **Also managed:** `~/.claude/hooks/bash-guard.py` (from `scripts/claude-hooks/`; `force` alone can't displace a hand-placed regular file — `dropStaleClaudeHooks` does). **Two deliberate exceptions that stay MUTABLE:** the `browser` skill (`~/.claude/skills/browser/{SKILL.md,browser}` are `mkOutOfStoreSymlink`s onto the live checkout in `scripts/browser-bridge/`, so edits apply with no switch), and `~/.claude/CLAUDE.md`, which is genuinely per-host (a plain regular file, unreferenced by `home.nix`) — host-specific and frequently edited in place.
- `.zshrc`, `.tmux.conf` etc. are read by the nix modules — read with offset/limit, they're large.

## Conventions
- Never `git add -A` — stage files individually.
- Commit + push so both hosts (workbench + laptop) can `git pull` then `home-manager switch`.
